### Q1. [2 Marks] Distinguish between Logical Address and Physical Address.
**Model Answer:**
A **Logical Address** (virtual address) is generated by the CPU while executing a program instruction. It exists purely in the logical address space abstraction.
A **Physical Address** is the actual hardware memory address loaded onto the memory bus to access a specific RAM chip byte. The hardware **MMU (Memory Management Unit)** translates logical addresses to physical addresses at runtime.

### Q2. [2 Marks] Define Internal Fragmentation and External Fragmentation.
**Model Answer:**
**Internal Fragmentation** occurs when allocated memory blocks are slightly larger than the requested payload; the unused space inside the allocated partition is wasted (characteristic of fixed partitioning and paging).
**External Fragmentation** occurs when total free memory is sufficient to satisfy an allocation request, but it is broken up into tiny non-contiguous blocks scattered across RAM (characteristic of variable partitioning and segmentation).

### Q3. [2 Marks] What is a Translation Lookaside Buffer (TLB)?
**Model Answer:**
A **TLB** is an ultra-fast hardware associative associative cache inside the MMU that stores recently used page-to-frame translations. It allows single-cycle physical address translation, avoiding the need for an extra memory access to read the Page Table from RAM.

### Q4. [2 Marks] What is Demand Paging and what is a Page Fault?
**Model Answer:**
**Demand Paging** is a virtual memory scheme where pages of a program are loaded into physical RAM only when demanded during execution (lazy swapping).
A **Page Fault** is a hardware trap raised by the MMU when a running process attempts to access a virtual page marked invalid (`valid-invalid bit = 0`), indicating the page currently resides on disk and must be fetched by the OS.

### Q5. [2 Marks] What is Belady's Anomaly and which page replacement algorithm exhibits it?
**Model Answer:**
**Belady's Anomaly** is the counter-intuitive phenomenon where increasing the number of physical page frames allocated to a process results in an *increase* (rather than decrease) in the total number of page faults. It occurs in non-stack algorithms like **FIFO (First-In, First-Out)**.

### Q6. [2 Marks] Define Thrashing in operating systems.
**Model Answer:**
**Thrashing** is a severe performance collapse that occurs when a system spends more time servicing page faults and swapping pages in/out of disk than executing useful user instructions. It happens when the sum of active working sets exceeds available physical memory.

### Q1. [5 Marks] Explain the step-by-step procedure of Page Fault Handling by the Operating System with a diagram.
**Model Answer:**
### Page Fault Handling Mechanism

```
  +---------------+               1. Memory Reference
  |      CPU      |-------------------------------------> [ Page Table ]
  +---------------+                                              |
          ^                                                      | 2. Invalid Bit Trap
          |                                                      v
          |                                             [ Operating System ]
          |                                                      |
          |                                                      | 3. Locate Page on Backing Store
          |                                                      v
          | 6. Restart                                    [ Disk Storage ]
          |    Instruction                                       |
          |                                                      | 4. Read Page into Free Frame
          |                                                      v
  [ Physical RAM  ] <------------------------------------+-------+
  Frame Allocated | 5. Reset Valid Bit in Page Table
```

#### Step-by-Step Sequence:
1. **Memory Access:** CPU accesses logical address. MMU checks Page Table and finds `valid bit = 0`.
2. **Trap to Kernel:** MMU signals a Page Fault Trap to the OS kernel.
3. **Context Save:** Kernel saves current process CPU registers and state.
4. **Locate Backing Store:** OS determines the target page's exact sector location on swap disk.
5. **Disk I/O:** OS finds a free physical frame in RAM (or executes page replacement if RAM is full) and initiates disk I/O to copy the page. The faulted process is placed in the Waiting queue.
6. **Update Page Table:** On I/O completion, OS records the new physical frame number in the Page Table and flips the valid bit to `1`.
7. **Instruction Restart:** Process moves to Ready Queue and resumes execution, restarting the exact instruction that triggered the fault.

### Q2. [5 Marks] Compare Paging and Segmentation memory management architectures.
**Model Answer:**
### Paging vs Segmentation

| Feature | Paging | Segmentation |
| :--- | :--- | :--- |
| **Concept** | Memory partitioned into fixed-size physical blocks (**Frames**) and equal logical blocks (**Pages**). | Program divided into variable-sized logical segments reflecting programmer modules (Code, Stack, Heap, Symbol Table). |
| **Address Structure** | One-dimensional address decomposed into `(Page Number, Page Offset)`. | Two-dimensional address consisting of `(Segment Number, Segment Offset)`. |
| **Visibility** | Completely invisible to programmer/compiler (handled by MMU/OS). | Visible to programmer/compiler as distinct functional units. |
| **Fragmentation** | Suffers from internal fragmentation (on the last page); **zero external fragmentation**. | Suffers from **external fragmentation** as segments dynamically grow/shrink; zero internal fragmentation. |
| **Protection & Sharing** | Uniform protection bits per page (read/write/exec). Sharing arbitrary pages is awkward. | Natural unit of protection and code sharing (e.g., entire shared library segment can be marked read-only). |

### Q3. [5 Marks] Calculate the Effective Memory Access Time (EMAT) given TLB hit ratio and access latencies.
**Model Answer:**
### Effective Memory Access Time (EMAT) Formula & Derivation

Let:
- $\alpha$ = TLB Hit Ratio (fraction of translations found in TLB)
- $t_{tlb}$ = TLB lookup time
- $t_{m}$ = Main memory access time

#### 1. Case: TLB Hit (Probability $\alpha$):
Physical frame address is resolved directly inside TLB. Only one main memory access is needed to fetch the actual operand:
$$\text{Time}_{\text{hit}} = t_{tlb} + t_m$$

#### 2. Case: TLB Miss (Probability $1 - \alpha$):
MMU searches TLB, misses, accesses the Page Table in main memory, updates TLB, and then accesses main memory for the operand:
$$\text{Time}_{\text{miss}} = t_{tlb} + 2 \cdot t_m$$

#### Effective Memory Access Time Formula:
$$\text{EMAT} = \alpha \cdot (t_{tlb} + t_m) + (1 - \alpha) \cdot (t_{tlb} + 2 t_m) = t_{tlb} + (2 - \alpha) \cdot t_m$$

#### Example Calculation:
If TLB access time is $20\text{ ns}$, memory access time is $100\text{ ns}$, and TLB hit ratio is $90\%$ ($\\alpha = 0.90$):
$$\text{EMAT} = 20 + (2 - 0.90) \times 100 = 20 + 1.10 \times 100 = \mathbf{130\text{ ns}}$$
*(Compared to $200\text{ ns}$ without TLB, EMAT is reduced by 35%).*

### Q2. [10/15 Marks] Explain Thrashing in detail. What causes it? How does the Working Set Model proposed by Peter Denning eliminate thrashing?
**Comprehensive University Solution:**
### Thrashing and the Working-Set Model

#### 1. What is Thrashing?
Thrashing is a catastrophic system state where the operating system spends virtually all its time moving pages back and forth between physical RAM and disk swap space, with CPU utilization collapsing toward near zero.

```
CPU
Utilization ^
            |          Optimal
            |         Operating
            |           Point
            |          /  \
            |         /    \
            |        /      \   <--- Thrashing Zone:
            |       /        \       CPU utilization drops steeply!
            |      /          \
            +-----+------------+-------------> Degree of Multiprogramming
```

#### 2. Root Cause of Thrashing:
1. As the OS increases the **Degree of Multiprogramming** to boost CPU utilization, physical RAM frames are divided among more processes.
2. Eventually, each process is allocated fewer frames than the minimum number required to support its active locality of execution.
3. Process $P_i$ faults and waits for disk I/O. The short-term scheduler notices CPU idle time and mistakenly increases multiprogramming by admitting another process.
4. Total demand for page frames explodes; page queues back up; CPU utilization plummets to near zero.

---

#### 3. The Working-Set Model (Peter Denning):
The Working Set Model uses the principle of **locality of reference** to track the exact set of pages an active process is referencing over a sliding time window.

- **Working-Set Window ($\Delta$):** A fixed parameter defining the past number of page references examined.
- **Working-Set $WSS_i(t,\Delta)$:** The set of distinct virtual pages referenced by process $P_i$ during the most recent $\Delta$ references.

```
Reference Stream: ... 2  6  1  5  7  7  7  7  5  1 [ t ]
                      |<------- Delta = 10 ------->|
Working Set WSS(t, 10) = { 1, 2, 5, 6, 7 }  --> Size = 5 pages
```

#### Prevention Algorithm:
1. The OS calculates total memory frame demand:
   $$D = \sum_{i} |WSS_i|$$
2. Let $M$ be total available physical frames in RAM.
3. **If $D \le M$:** All processes have their entire working set resident in memory. The system runs at peak efficiency with minimal page faults.
4. **If $D > M$:** Total demand exceeds memory capacity! Thrashing is imminent. The OS **suspends (swaps out)** an entire process, frees its allocated frames to other processes, and lowers $D$ until $D \le M$.
